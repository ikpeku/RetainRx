# Engineering Rules

Binding for every contributor, human or AI. If a rule blocks you, propose a change to this file in a PR. Don't silently break it.

## 1. Spec-driven workflow

1. **The spec leads, code follows.** Before coding a task, read its row in [implementation-plan.md](implementation-plan.md) and every spec section it references.
2. **No unspecified behaviour.** If the spec is silent or ambiguous, stop and add an open question to [decisions.md](decisions.md), or propose a spec edit. Don't invent product behaviour in code.
3. **Specs change in the same PR as the code.** If you change the schema, update [data-model.md](data-model.md). An endpoint means [api-spec.md](api-spec.md). Rexa copy or flow means [conversation-design.md](conversation-design.md).
4. **Track progress.** Every PR updates [progress.md](progress.md) (checkbox + log line).
5. **One task per PR**, titled with the task ID: `P4.3: Record action with undo`.

## 2. Domain invariants (never violate)

- **Tenant isolation:** every tenant query is scoped by `pharmacy_id` from auth context, never from user input. Every new endpoint gets a cross-tenant test.
- **Consent first:** no medication data is stored, and no proactive message is sent, without active consent with the right scope.
- **Experiment integrity:** `experiment_arm` is assigned once and never changed except to `excluded`. Cycle arms are frozen. Nothing in the API or admin UI edits them.
- **Idempotency:** inbound messages dedupe on `wa_message_id`, counter actions on `client_action_id`, and scheduled sends are never resent once Meta has accepted them.
- **24h window:** free-form WhatsApp messages only within 24h of the customer's last inbound message. Otherwise use an approved template.
- **Messaging hours:** proactive sends only between 09:00 and 19:00 Africa/Lagos.
- **No medical advice from Rexa.** Ever.
- **AI proposes, humans confirm.** AI output never directly creates plans, sends messages, or changes state.
- **Money in kobo** (`bigint`), never floats. Format as ₦ only at the edge.
- **Time:** store instants as UTC `timestamptz`; compute business dates in `Africa/Lagos` via `packages/domain/time.ts`. Never use `new Date()` for business "today". Inject a clock.
- **Derived statuses** (`due/overdue/lapsed`) are computed with `domain.cycleStatus`, never stored.
- **Events:** every state change writes an `events` row in the same transaction.

## 3. Code structure

- Business logic lives in `packages/domain` and `packages/rexa` as **pure functions** (no I/O, clock injected). Apps are thin adapters.
- API routes: `apps/api/src/routes/<area>/<resource>.ts` with a sibling `schema.ts` (Zod). Handlers call services; services call repositories.
- Repositories take `(tx, pharmacyId, …)`. No raw SQL in routes.
- Jobs: one file per queue in `apps/worker/src/jobs/`, and handlers must be idempotent.
- UI: server components by default; client components only for interactivity. Shared components go in `packages/ui`.
- Copy shown to customers lives only in `packages/rexa/copy/`. No inline strings in handlers.
- Feature constants (3-day lead, 7-day delay, 2-day due window, 7-day overdue, 2h stock freshness, 10-min query timeout) live in `packages/domain/constants.ts` or pharmacy settings. No magic numbers.

## 4. TypeScript and style

- `strict: true`, `noUncheckedIndexedAccess: true`. No `any` (use `unknown` + Zod). No non-null `!` except in tests.
- Validate all external input (HTTP, webhooks, AI output, env) with Zod at the boundary.
- Names: `camelCase` in TS, `snake_case` in SQL and JSON API payloads. Files are `kebab-case.ts`.
- Errors: throw typed `AppError(code, status, message)`. Never leak stack traces or SQL to clients.
- Prefer small functions, early returns, and no clever abstractions before the third use.
- Comments explain *why*, not *what*.

## 5. Testing

| Layer | Tool | Required for |
|---|---|---|
| Unit | Vitest | All `domain` and `rexa` functions: every state transition and every status/metric edge case |
| Integration | Vitest + Testcontainers Postgres | Every API route (happy path, auth failure, cross-tenant), every job |
| AI | Recorded fixtures (golden sets) | Extraction and intent classification; live evals on demand |
| E2E | Playwright | Counter Panel core flows, owner login, dashboard |
| Contract | Zod schemas | Webhook payload fixtures from Meta and Paystack |

- Tests never call real WhatsApp, Claude, Paystack or Termii. Use fakes in `packages/*/testing`.
- A bug fix starts with a failing test.
- Coverage target: ≥ 90% lines on `packages/domain` and `packages/rexa`. Other packages are not gated.

## 6. Database

- Migrations are generated by drizzle-kit, reviewed, and committed. **Never edit a migration that has been merged.**
- Every migration is backward compatible with the currently deployed code (expand → migrate → contract).
- Add indexes for every new list query. Explain them in the PR.
- No cascading deletes on tenant data except in the erasure path.

## 7. Security and privacy

- Follow [security-and-privacy.md](security-and-privacy.md).
- Never log phone numbers, names, message bodies or medicine-to-person links.
- Never send customer name or phone to the AI provider.
- Secrets only via env. Never commit `.env`.
- New third-party services (anything that receives data) need an ADR.

## 8. Git and PRs

- Branches: `p4.3-record-action`. Conventional commits: `feat(counter): record collected refill (P4.3)`.
- A PR must include: task ID, what changed, spec files updated, test evidence, and screenshots for UI.
- CI must be green. At least one review (an AI review counts during solo development, but a human merges).
- `main` is always deployable. Staging auto-deploys from `main`; production is a manual promote.

## 9. Definition of done

- [ ] All acceptance criteria in the plan row are met
- [ ] Tests added and passing; lint and typecheck are clean
- [ ] Specs updated (data model / API / conversation / decisions)
- [ ] `progress.md` updated
- [ ] No PII in logs (checked)
- [ ] Deployed to staging and smoke-tested (for user-facing tasks)
